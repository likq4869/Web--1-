## 1. 执行总原则（继承 AGENTS.md，不重复）

1. **一次只做一个提示词框**。不跨框并行。
2. **多文件/跨层改动先出设计方案**（分层归属、接口签名、数据流、边界），确认后再写码。
3. **小步提交**：每个可验证单元自检一次。
4. **领域逻辑必须配单元测试**，测试与实现同时产出。
5. **门禁不能跳**：每完成一项跑 `ruff + mypy + pytest`（后端）与 `lint + type-check + build`（前端），必须全绿。
6. **禁止** TODO / FIXME / `pass` 桩 / 注释掉的代码 / 裸 `except` / 前端 `any`。
7. **前端改动前必读 `design.md`**；新增组件/页面后同步更新 `design.md` §18.1 对应关系表。

## 2. P3-0：认证 API（G-01）★最高优先级

**为什么第一**：后端 `core/security.py` 已有 JWT 签发/校验与 bcrypt，但**没有路由层**。前端 `auth.ts` 四个接口全部 404 → 登录永远失败 → 路由守卫重定向 → 管理后台完全不可用。**这是唯一让整站无法运行的缺口。**

### 2.1 范围

| 交付 | 内容 |
|---|---|
| **迁移 0007** | `users` 表新增 `password_hash`（TEXT, nullable）；`user_role` 枚举补 `admin`/`reviewer`/`observer` 三值 |
| 后端路由 | `app/api/v1/auth.py`：`POST /login`、`POST /refresh`、`POST /logout`、`GET /me`、`POST /bind-student` |
| 仓储 | `app/repositories/user.py`：按用户名/学号查用户（含 `password_hash`、`role`、`status`） |
| 服务 | `app/services/auth/service.py`：校验密码 → 签发 access/refresh → 组装 `CurrentUser` |
| Schema | `app/schemas/auth.py`：`LoginBody`、`LoginResult`、`RefreshBody`、`BindStudentBody`、`CurrentUserOut` |
| 种子 | `app/seed_demo.py` 补 `super_admin` 账号（bcrypt 哈希，**明文不入库**） |
| 前端 | **不改**（`api/auth.ts` 已就绪）。仅需核对字段名与后端一致 |
| 测试 | `tests/test_api_auth.py`：登录成功/密码错误/用户禁用/无 token 取 me/刷新/过期 token/角色守卫/绑定学号 |

### 2.2 关键设计决策（2026-11-17 已全部确认）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 刷新令牌存哪？ | **无状态 JWT**（用现有 `create_refresh_token`，`token_type=refresh`）。不建表，改动最小 |
| 2 | `UserRole` 枚举以哪侧为准？ | **后端补齐**。`USER_ROLE_VALUES` 加 `admin`/`reviewer`/`observer`（走迁移改 Enum），与前端 9 值对齐 |
| 3 | `CurrentUser.id` 类型 | **前端改为 `id: string`**（后端 `users.user_id` 本就是 String，零妥协） |
| 4 | `display_name` / `source_ids` | **响应层派生**（`display_name = username`，`source_ids` 查关联，无则 `[]`），零迁移 |
| 5 | 小程序 `bind-student` 接口 | **本阶段一并实现**（P4-1 依赖） |
| 6 | `D:\1-Miniconda\envs\helmet-guard` | **保持现状不动**（项目 `.venv` 已含完整推理栈且能过全部门禁；Conda 环境仅作离线推理实验，缺 sqlalchemy 跑不了采集进程） |

**前端契约（后端必须逐字照此返回）：**

```ts
LoginResult  { access_token, refresh_token, token_type, expires_in, user }
CurrentUser { id: string, username, display_name, role, source_ids: string[] }
```

> ⚠️ **前端需同步改两处**（实测发现）：
> 1. `api/types.ts` 的 `CurrentUser.id`：`number` → `string`（后端 `users.user_id` 是 String）
> 2. `api/types.ts` 的 `CurrentUser.source_ids`：`number[]` → `string[]`
>    （后端 `sources.source_id` 是 **String**，如 `gate-east`）
>
> `source_ids` 在前端**无任何消费点**（仅类型定义），改动零风险。

### 2.2.1 分层归属与接口签名（设计已确认）

```
app/api/v1/auth.py            ← 路由层：只做参数校验 + 包络，无业务逻辑
app/services/auth/service.py  ← 服务层：归属校验、令牌签发、用户组装
app/repositories/user.py      ← 仓储层：按 username / student_id 查 users
app/schemas/auth.py           ← Pydantic 出入参
app/core/security.py          ← ✅ 已就绪，本次不改
```

```python
class AuthService:
    def __init__(self, session: Session) -> None: ...
    def login(self, username: str, password: str) -> LoginResult: ...
    def refresh(self, refresh_token: str) -> RefreshResult: ...
    def current_user(self, subject: str) -> CurrentUserOut: ...
    def bind_student(self, subject: str, student_id: str) -> CurrentUserOut: ...
```

### 2.2.2 已核实的实现细节（照做，别重新踩）

| 项 | 实测结论 |
|---|---|
| 前端路径 | `api/auth.ts` 的 `AUTH_BASE='/v1/auth'` + `baseURL='/api'` → 实际 `/api/v1/auth` ✅ 与后端 `APIRouter(prefix="/api/v1/auth")` 一致 |
| 前端刷新路径 | `request.ts` 的 `REFRESH_PATH='/api/v1/auth/refresh'` ✅ 已匹配 |
| 学生关联 | **没有独立关联表** —— `students.user_id` 是唯一外键指向 `users.user_id`（`ondelete="SET NULL"`）→ 绑定即 `UPDATE students SET user_id=?` |
| `source_ids` 来源 | `vehicles` 表**无** `source_id` 字段 → 需经 `identity_resolutions` / `passes` 的 `source_id`（String）关联该用户名下车辆 |
| `source_ids` 类型 | `sources.source_id` 是 **String**（`gate-east`），前端 `number[]` **类型写错**，需改 `string[]` |
| 路由静默丢失 | `app/main.py` 用 `with suppress(Exception)` 包路由导入 → 导入失败会被静默吞掉，路由不注册且无报错。**必须加测试断言路由存在** |
| 枚举迁移 | SQLite 的 `Enum` 是 VARCHAR + CHECK → 改枚举值需**重建表**（新表 → 拷数据 → 删旧 → 改名），迁移必须可逆且不丢数据 |
| 禁用用户 | 禁用后旧的 access/refresh 令牌必须失效 → `refresh` 与 `me` 都要查库确认 `status == 'active'` |
