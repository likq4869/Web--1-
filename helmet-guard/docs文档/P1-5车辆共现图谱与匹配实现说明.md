## 1. 共现计算公式与置信度依据

### 1.1 时间窗口划分

```
窗口索引 = floor(UTC 纪元秒 / 窗口秒数)，默认窗口 5 分钟
```

| 设计点 | 取值 | 依据 |
|--------|------|------|
| 窗口长度 | 5 分钟 | 同宿舍楼/同班同学结伴出行的典型时间粒度；过短拆散同行人，过长误判前后脚陌生人 |
| 跨小时/跨天 | 纪元除法天然对齐，无特殊处理 | 实测 `09:59:30` 与 `10:00:30` 落相邻窗口 |
| naive 时间 | 一律视为 UTC | 与 SQLite `CURRENT_TIMESTAMP` 及领域层约定一致 |

### 1.2 相似度与置信度

```
jaccard(u,v) = |A ∩ B| / |A ∪ B|        # 同行比例
conf(u,v)    = jaccard × min(1, shared / 3)   # × 次数饱和因子
```

| 设计点 | 规则 | 依据 |
|--------|------|------|
| Jaccard | 两空集返回 0.0（而非 1.0） | 无证据≠完全相同，避免从未出现的车被误判共现 |
| 次数饱和 | `min(1, shared/3)` | 仅共现 1 次即使 jaccard=1 也只给 1/3（偶然同行不采信）；≥3 次饱和 |
| 双重钳制 | resolver 侧再映射到 [0.30, 0.55] | 见 P1-3：共现是"身份辅助"，单独永远无法 BIND |

### 1.3 匹配算法（含降级路径）

```
已知车→学号 + 共现置信度 → 未知车 × 学号 利润表（取该未知车与该学号名下各已知车的最大置信度）
→ 带权二部图最大匹配（一车一人、一人一车）→ 低于 min_conf(0.60) 的边过滤
```

| 路径 | 算法 | 何时走 |
|------|------|--------|
| 主路径 | 匈牙利算法（`scipy.optimize.linear_sum_assignment`，总利润最大） | scipy 可用时 |
| 降级路径 | 纯 Python 贪心（按利润降序，双方未占用才接受） | `use_scipy=False` 或导入失败自动降级 |

- 取**最大**而非平均：一次强同行（如连续 5 天同窗口）的证据力高于多次弱同行的平均。
- 贪心确定性：排序键 `(-利润, 未知车, 学号)`，并列字典序优先，跨进程可单测断言。
- 过滤保持一对一：最优匹配的子集仍满足约束（已用单测证明）。
- 一对一由**算法结构**保证：匈牙利每行/列至多选一次；贪心用两套占用集合互斥。

## 2. 服务层与定时任务

| 入口 | 行为 | 调用时机 |
|------|------|----------|
| `rebuild_cooccurrence(session)` | 全量：判定历史 → 按车分组 → `compute_cooccurrence` → 清空后逐对 upsert | 每日凌晨离线任务 |
| `update_cooccurrence(session, vehicle_id, occurred_at)` | 增量：该车与同窗口其他车配对，`window_count +1`，jaccard 保持原值等夜间刷新；同窗口重复调用去重 | 每次通行后 |
| `hints_for_vehicle(session, vehicle_id)` | 取 Jaccard 最高的若干对，映射对方绑定学号（无绑定跳过），供 resolver `cooccur_hints` | resolver 调用前 |
| `scripts/rebuild_cooccurrence.py --db <路径>` | 手动全量重算入口（Celery beat 接入前用 cron/计划任务每日凌晨执行） | 运维手动/定时 |

**增量设计的两个关键决策**：
1. `updated_at` 存**事件时刻**而非墙钟时间：去重基准是事件窗口，用 `func.now()` 会导致同窗口重复调用判不中去重。
2. 增量只保证计数单调准确，Jaccard 精确值由夜间全量重算保证（单次增量不重算全矩阵是 O(1) vs O(n²) 的取舍）。

## 5. 已知限制与后续计划

**已知限制**
1. 增量更新的 `jaccard` 是旧值，精确值依赖夜间全量重算；若夜间任务漏跑，矩阵会缓慢失真（计数仍准）。
2. 利润表取"最大共现置信度"：某学号名下车越多，偶然高共现的概率越高；后续可在 P2 用"出现次数加权"修正。
3. `hints_for_vehicle` 只看对方车辆的**当前**绑定学号；若绑定关系在共现之后变更，历史提示不回溯。
4. Celery beat 尚未接入：当前用脚本 + 操作系统定时任务，接入 Celery 后把 `main()` 核心两行搬进 task 即可。

**后续计划**
1. P1-6：身份管理 API 与后台页面（共现提示纳入审核界面，展示 Jaccard 与同行窗口数）。
2. P2-1：积分域（共现推断的绑定走人工确认后再生效，符合"人工兜底"原则）。
