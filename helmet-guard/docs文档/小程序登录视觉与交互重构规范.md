## 第 0 章 结论：v2.0 是否最优 · 本次重构定位

### 0.1 直接回答

> **v2.0 流程规范是「流程模型层面」的最优解，但不是「可交付的视觉实现」。**

v2.0 解决了流程正确性（静默登录、渐进授权、双层反馈、状态机单一源），这些是骨架，方向正确且已联网核验。
但它**没有**解决以下 6 项，而这 6 项才是你这次说的「样式设计、盒子布局、交互效果要丝滑」：

| # | v2.0 的缺口 | 证据 | 本次处理 |
|---|---|---|---|
| **G1** | **间距不统一**。当前 `auth.scss` 里同时存在 `6px`（label 下边距）、`10px $space-3`（input padding）、`$space-4 + 2px`（=18px，卡片 padding）、`14px $space-3`（avatar 间距）、`2px`（各种微调）等 **20+ 个非刻度值** | `auth.scss` / `LoginSheet.scss` 实测 | 第 1 章：重建 8pt 刻度 + 语义别名 |
| **G2** | **没有间距层级语义**。间距是「随手写的数字」而非「按元素亲密度推导」 | 飞书规范：「间距应随着组件亲密性关系的变化而变化，关系越亲密，间距越小」 | 第 1 章：引入 5 级亲密度模型 |
| **G3** | **动效是拼凑的**。`card-rise`（250ms）/`pop-confirm`（250ms）/`sheet-jelly`（300ms）/`pressable`（150ms）各写各的，**没有区分空间动效与效果动效** | M3 规范：Spatial（会过冲）与 Effects（阻尼=1.0 绝不���冲）必须分用；「An overshooting color looks broken」 | 第 6 章：按 M3 语义重建双令牌体系 |
| **G4** | **输入框是 8 态状态机的残缺版**。当前只有「常态 / focus」两态，无 error 态、无 filled 态、无 disabled 态 | Material 输入字段规范要求 8 态全部成立 | 第 5 章：完整 8 态 + 状态驱动派生 |
| **G5** | **步骤指示器是「装饰」而非「状态机」**。当前 4 个点用 `is-done`/`is-current` 二值区分，**没有 error 态**，且连接线不可见 | 飞书：状态至少含未开始/当前/完成/错误；TDesign：4 态 | 第 4 章：4 态 + 进度连接线 |
| **G6** | **Mock 通道在生产代码路径上** | 见第 7 章实测 | 第 7 章：全链路真实数据 |

### 0.2 本次重构的核心主张

> **「丝滑」不是动画多，而是「节奏统一 + 状态可预期 + 反馈有因果」。**

具体落地为三条铁律：

```
① 盒盒之间只有一个间距来源（语义别名），不再出现字面量。
   → 改一处，全局生效；不会再出现「这里 8px、那里 10px」。

② 动效按「是否会产生过冲」二分，而非按「时长」二分。
   → 位置/尺寸动效用过阻尼（一次到位，不晃）
   → 颜色/透明度动效用临界阻尼（绝不回弹）

③ 任何状态变化都有明确的视觉因果：
   → 按下有回弹、加载有占位、错误有定位、成功有确认
   → 动效不超过 350ms，且 reduced-motion 下直接出终态。
```

## 第 1 章 间距系统重建（统一盒子间隔）

### 1.1 官方间距规范（联网核验）

| 来源 | 结论 |
|---|---|
| 飞书《响应式设计指南》 | 「在 UD 的规则中定义以 **8px 为最小单元格**，用 8 的倍数来定义模块间距和元素的尺寸」；移动端/小程序：**4 列 / 8 槽 / 16 边距** |
| PixelCake《8pt grid》 | 刻度表：`4 / 8 / 12 / 16 / 24 / 32 / 40 / 48 / 64 / 80 / 96`；「4 和 12 用于微调，16 到 48 用于大多数元件与区块」 |
| 田甜甜《UI 基本设计规范》 | 「标签与输入框距离 **4 / 8**」「字段与字段间距 **16 / 24**」「表单区块与按钮距离 **24 / 32**」「图标与文字 **4 / 8**」「按钮与其他元件 **16**」 |
| Adobe AEM 移动端表单 | 「字段与字段间隔 16–24px，分组间隔 24–32px，页面边距 16px」 |

> **8 与 4 的分工**（飞书原文）：「8px 作为最小单元格……使用 4px 会导致整个页面分割非常细，设计复杂度增加」。
> 但 4px 与 12px 必须保留（PixelCake：「好的 8pt 间距系统通常会保留 4px 与 12px，因为真实产品不会永远刚好落在 8 的倍数上」）。

### 1.2 本项目间距刻度（在 `tokens.scss` 中落地）

```scss
/* 8pt 基础网格：4 为半格微调，8 为原子格，其余为 8 的倍数 */
$space-1:  4px;    /* 半格微调：icon↔文字、helper↔input */
$space-2:  8px;    /* 原子格：小元件 gap、标签↔控件 */
$space-3:  12px;   /* 1.5 格：紧凑表单内元素 */
$space-4:  16px;   /* 2 格：主节奏：卡片内边距、字段间距 */
$space-5:  20px;   /* 2.5 格：页面左右边距（移动端） */
$space-6:  24px;   /* 3 格：区块间距、分组间距 */
$space-8:  32px;   /* 4 格：大区块间距 */
$space-10: 40px;
$space-12: 48px;
```

> **保留 `$space-5: 20px`**（非 8 的倍数）是**有意为之**：飞书规范明确「安全边距需遵循产品本身的规则……People 业务线考虑其业务场景特化为 20px」。
> 移动端页面边距用 20px 而非 16px 的理由：本项目有 `4 列栅格 / 8 槽 / 16 边距` 的官方基线，
> 但登录页是**单列表单**（不是四宫格工具），16px 边距在 375px 屏上会让输入框过宽（319px），
> 而 20px 边距给出 335px —— 更接近单列表单舒适区，且与 `home`/`mine` 页现有 20px 边距**保持一致**（跨页一致性优先于单页最优）。

### 1.3 语义别名（唯一允许在组件里出现的间距写法）

> **组件内禁止写 `margin-bottom: 16px`，只允许写 `margin-bottom: $gap-field`。**

```scss
/* ── 语义间距别名（组件内唯一允许的间距写法）────────────────────── */

/* 元素内部：紧密度最高 */
$gap-icon-text:   $space-1;    /* 4px  图标 ↔ 文字 */
$gap-label:       $space-2;    /* 8px  标签 ↔ 控件 */
$gap-helper:      $space-1;    /* 4px  控件 ↔ 辅助/错误文字 */
$gap-badge-inner: $space-1;    /* 4px  徽章内边距 */

/* 同组元素之间 */
$gap-inline:      $space-2;    /* 8px  同行小元件 */
$gap-btn-group:   $space-3;    /* 12px 按钮组内按钮间距 */
$gap-field:       $space-4;    /* 16px 表单字段之间 */
$gap-card-inner:  $space-4;    /* 16px 卡片内元素 */

/* 分组 / 区块之间 */
$gap-group:       $space-6;    /* 24px 字段分组之间 */
$gap-section:     $space-8;    /* 32px 大区块之间 */

/* 容器内边距 */
$pad-card:        $space-4;    /* 16px 卡片内边距 */
$pad-sheet:       $space-5;    /* 20px 弹窗内边距 */
$pad-page-x:      $space-5;    /* 20px 页面左右边距 */
$pad-page-y:      $space-6;    /* 24px 页面上下边距 */

/* 页面边距（安全区） */
$page-padding-x:  $pad-page-x;
$page-padding-y:  $pad-page-y;
```

### 1.4 亲密度模型（间距推导依据）

> 飞书规范：「在定义间距时，需要注意到元素之间的亲密关系，通常间距应随着组件亲密性关系的变化而变化，关系越亲密，间距越小。」

```
亲密等级        间距        典型元素
──────────────────────────────────────────────────────────
L0 原子内       4px         icon↔文字、徽章内边距
L1 标签对       8px         label↔input、chip↔chip
L2 同组         12–16px     input↔input、按钮↔按钮
L3 分组         24px        基本信息组 ↔ 联系方式组
L4 区块         32px        卡片 ↔ 卡片、步骤条 ↔ 内容
L5 页面         20/24px     页面边距 + 安全区
```

### 1.6 溢出保护（每个盒子都要有）

```scss
/* 所有 flex 子项必须允许收缩，否则长文本必然溢出 */
%flex-safe {
  min-width: 0;
}

/* 单行截断 */
%truncate {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}

/* 多行限高 */
%clamp-2 {
  display: -webkit-box;
  -webkit-line-clamp: 2;
  -webkit-box-orient: vertical;
  overflow: hidden;
}
```

> 小程序 `text` 默认 `display: inline`，长文不换行会溢出容器 —— **这是 D11 的根因**。
> 规则：**每个含文字的 flex/grid 子项都要 `min-width: 0`；每个可能变长的文本都要明确截断策略。**

## 第 2 章 登录链路页面骨架重构

### 2.1 页面职责重新划分（关键决策）

> **当前 `auth.vue` 承载 4 个步骤，是「后端接口的镜像」。重构后它只承载「资料补全 + 同意」。**

```
┌────────────────────────────────────────────────────────────────┐
│ App.vue onLaunch                                                │
│   └─ silentLogin() → 零感知建立身份（失败 → 游客态）              │
│       ↑ D12：utils/auth.ts 需补 silentLogin 实现                 │
└────────────────────────────────────────────────────────────────┘
                            │
   ┌────────────────────────┴────────────────────────┐
   │ 游客态：home / index / mine 均可浏览             │
   │   触发需身份功能 → LoginSheet（弹窗，非整页）     │
   └────────────────────────┬────────────────────────┘
                            │ 弹窗内 wx 一键登录
                            ▼
                  ┌──────────────────────┐
                  │ LoginSheet (wx 步)   │──取号──▶ LoginSheet (phone 步)
                  │ 微信一键登录          │              本机号码一键绑定
                  └──────────────────────┘
                            │ has_phone=1 && has_profile=0
                            ▼
                  ┌──────────────────────┐
                  │ auth.vue (学籍步)      │  ← 整页，只做资料补全
                  │ 头像昵称 + 组织级联     │
                  │ + 学号 + 姓名          │
                  └──────────────────────┘
                            │ 保存成功
                            ▼
                  ┌──────────────────────┐
                  │ auth.vue (同意步)      │  ← 知情同意（也可 ?consent=1 直达）
                  └──────────────────────┘
                            │ 确认
                            ▼
                          switchTab(home)
```

**为什么取号留在弹窗、资料补全留在整页？**

| 维度 | 取号放弹窗 | 资料补全放整页 |
|---|---|---|
| 认知负荷 | 低：一次点一个系统弹窗 | 高：8 个字段，需滚动 |
| 页面形态 | 底部动作面板，聚焦单任务 | 整页表单，需输入键盘 |
| 微信规范 | ✓ `getPhoneNumber` 适合按钮触发 | ✓ 表单需要整页 + 原生返回 |
| 失败成本 | 低，关掉弹窗即回原页面 | 中，需原生返回 |
| **结论** | ✓ | ✓ |

### 3.3 弹窗动效（重构：果冻回弹 → 双阻尼规范）

**当前实现的 `sheet-jelly` 问题**：
```scss
@keyframes sheet-jelly {
  0%   { opacity: 0; transform: translateY(24px) scale(0.96); }
  40%  { opacity: 1; transform: translateY(-2px) scale(1.03); }   /* ← 过冲 */
  60%  { opacity: 1; transform: translateY(-2px) scale(1.03); }
  100% { opacity: 0; transform: translateY(0) scale(1); }
}
```
问题：
1. **过冲两次**（40% 和 60% 同一帧值）→ 违反「只回弹 1 次」
2. `translateY(-2px)` 位移虽在 4px 内，但**结构位移用欠阻尼是错的**（M3：Spatial 位移属"空间动效"，弹窗进场应一次到位）
3. `opacity` 与 `transform` 混在一个关键帧里，但 opacity 属 **Effects** 类（不该过冲）

**重构为分离式双关键帧**：

```scss
/* 进场：位置（Spatial）用过阻尼，一次到位无过冲；透明度（Effects）用标准缓动 */
@keyframes sheet-in {
  from { transform: translateY(24px) scale(0.98); }
  to   { transform: translateY(0) scale(1); }
}
@keyframes sheet-fade {
  from { opacity: 0; }
  to   { opacity: 1; }
}

.sheet {
  animation:
    sheet-fade $duration-base $ease-standard both,
    sheet-in   $duration-slow $ease-overdamped both;
}
```

> 依据 M3 Expressive：「Spatial = anything that moves, resizes, rotates, changes corners or morphs（**会过冲**）；Effects = color and alpha（**不该过冲**）」。
> 本项目对「结构位移」取更保守的**过阻尼**（`design.md` 铁律⑤：吸附/结构位移用过阻尼，无过冲），
> 对「透明度」用标准缓动（`$ease-standard`）。

### 3.4 按压回弹（主按钮）

```scss
.primary-btn {
  transition: transform $duration-fast $ease-overdamped,
              opacity   $duration-fast $ease-overdamped;
}
.primary-btn:active { transform: scale(0.96); }
```

> 依据 M3「按钮按压的形状/尺寸变化应使用 effects 弹簧：ζ=1、stiffness=1600，因此**按压反馈不会回弹**」。
> 即：按压**不该**有回弹，回弹只留给「成功」等积极语义。
> `design.md` §9.8.2 A「按压回弹」实为「按下缩 + 松手归位」，`scale(0.96)` 属当前一致做法，**保留**。

## 第 4 章 步骤指示器重构

### 4.1 官方规范（联网核验）

| 来源 | 要求 |
|---|---|
| 飞书《步骤条》 | 「节点个数通常建议 **3-7 个**」「横向步骤条推荐使用 **24px 的步骤间距**」「每个步骤节点宽度保持一致，**等宽自适应**」「尽量避免嵌套步骤条」 |
| TDesign Steps | 状态：`default`（未完成）/ `finish`（已完成）/ `process`（进行中）/ `error`（错误） |
| MDN / WAI | 当前步骤加 `aria-current="step"`；同一组只标记一个当前 |
| WAI 多页表单 | 「在可能时为已完成步骤提供链接供用户回看」「回到已完成步骤时，当前步骤中已输入的数据应被保存」 |
| WooDawn | 「指示器空间不足时可缩略为『第 2 步，共 4 步』一行文字，**不要横向滚动**才能看到当前位置」 |
| 飞书 | 「**当前步骤、已完成和失败必须有文字，不能只变色**」 |

### 4.2 当前实现的问题

```
现状：  ①  登录  >  ②  手机  >  ③  学籍  >  ④  同意
        ↑ 圆点+文字+箭头图标，无连接线进度感
        ↑ 只有 is-done / is-current 二值，无 error 态
        ↑ ">" 箭头是 UniIcons forward，不是进度连接线
        ↑ 步骤间距不均（数字圆点 22px vs 文字高度不同）
```

### 4.3 目标形态（连接线 + 4 态）

```
  ①━━━━━━②━━━━━━③──────④
  登录   手机   学籍    同意
  ✓      ✓      ●      ○
```

**结构**：
```
┌──────────────────────────────────────────────┐
│  ┌────┐  ━━━  ┌────┐  ━━━  ┌────┐  ──  ┌────┐ │
│  │ ✓  │      │ ②  │      │ ③  │      │ ④  │ │
│  └────┘      └────┘      └────┘      └────┘ │
│   登录         手机         学籍        同意   │
└──────────────────────────────────────────────┘
   ↑ 节点 22px 圆    ↑ 连接线 2px，高度 2px
```

### 4.4 规格

| 项 | 规格 |
|---|---|
| 节点尺寸 | `22px` 圆，`$radius-full` |
| 节点间距 | 连接线长度自适应（`flex: 1`），两端各留 `8px` |
| 连接线 | 高 `2px`，圆角 `$radius-full` |
| 节点文案 | `12px`，单行，不换行 |
| 步骤条间距 | 横向步骤间距 `24px`（飞书）→ 连接线区 `flex: 1` + 两侧 `12px` |
| 整体 | 与内容间距 `16px`（`$gap-field`） |
| 容器 | `overflow: hidden` + `flex-wrap: nowrap`（防溢出） |
| 溢出策略 | 4 步 × (22 + 12) + 文案 ≈ 需 ≤ 335px；**若不足则切换 compact 形态**（见 4.5） |

### 4.5 响应式降级（compact 形态）

依据 WooDawn「指示器空间不足时可缩略为『第 2 步，共 4 步』一行文字」。

**触发条件**：容器宽度 < 300px（极窄机型）或步骤文案总宽 > 容器宽。
**降级形态**：
```
第 2 步 / 共 4 步 · 手机
████████████████░░░░░░░░  ← 进度条（2px 高）
```

> 小程序无容器查询（`:has()` / `@container` 禁用，见 `AGENTS.md` §10），
> 改用 **JS 测量**（`uni.createSelectorQuery`）或**纯长度预估**（按文案字数估算）。
> 本项目采用**纯长度预估**：4 步固定、中文每字 12px，`总宽 = Σ(22 + 6 + 字数×12) + 3×24`。
> 预估 > 容器宽 → 降级 compact。

### 4.6 状态样式（4 态）

| 状态 | 节点底色 | 节点字色 | 节点文字 | 连接线 |
|---|---|---|---|---|
| `done`（已完成） | `$color-primary` | `$color-surface` | ✓ | `$color-primary` |
| `current`（当前） | `$color-primary` | `$color-surface` | 序号 | `$color-surface-3`（左段） |
| `error`（出错） | `$color-danger` | `$color-surface` | ! | `$color-danger` |
| `todo`（未开始） | `$color-surface-2` | `$color-text-3` | 序号 | `$color-surface-3` |

> **必须用形状 + 文字表意，不只靠颜色**（飞书 STEPS-R02 / WCAG 1.4.1）。
> ✓ 与 ! 是形状差异，色觉障碍用户也能分辨。

## 第 5 章 表单系统重构（八状态状态机）

### 5.1 官方规范（联网核验）

Material Design 文本输入字段规范：

> 「一个控件八种状态别只画两种……完整的输入字段至少要在八种组合下都成立：
> **空值未聚焦、空值聚焦、有值未聚焦、有值聚焦、错误未聚焦、错误聚焦、禁用、只读**。」

> 「这套规范里最核心的发明是浮动标签 floating label……在空值时它是占位说明，
> 在聚焦或有值时它缩小上浮变成字段的『名字』。」

> 「**不要用 placeholder 冒充标签**。placeholder 在输入后消失用户失去上下文，
> 而且很多读屏软件对 placeholder 的播报优先级低于 label。」

> 「用 **transform** 做位移和缩放，不要用 font-size（会触发重排导致文字闪烁）。」

> 「描边式聚焦时边框从 1px 变 2px 如果不做补偿内容会整体位移 1px，视觉上就是『输入的时候字抖了一下』。」

### 5.2 本项目选型：Filled 变体 + 外部标签

| 变体 | 特点 | 适用 | 本项目 |
|---|---|---|---|
| **Filled（填充式）** | 有底色，视觉重量重，底色本身是分组信号 | 密度高、字段成组（设置页、筛选面板） | — |
| **Outlined（描边式）** | 留白多、边界轻 | 表单是页面主角（注册、结算、问卷） | ✓ 登录链路 |
| **Underline（下划线）** | 极简 | 极简登录页 | — |

> Material 规范：「**关键在于不要混用**……我见过一个页面里上半部分是填充式、下半部分是描边式，原因是两拨人分别开发的。」
> 本项目**统一使用 Filled 变体**（因为小程序 `design.md` §3.2.4 明确：**输入框是 1px 边框白名单**，且项目已有 `$color-surface-2` 底 + `$color-border` 边框的双层结构）。
> **但标签用外部标签（label 在上）**，不用浮动标签 —— 理由见 5.3。

### 5.3 为什么不用浮动标签

| 考量 | 结论 |
|---|---|
| Material 规范「Filled 变体适合密集场景，Outlined 适合表单主角」 | 本项目输入框有底色（Filled） |
| Material 浮动标签实现需要「标签背景遮盖」来挖边框缺口 | 小程序 `text` 组件**不支持伪元素挖缺口**，`label` 需与 `input` 绝对定位重叠 → 复杂且易错 |
| Material「紧凑版 40dp 时往往干脆不显示浮动标签改用外部标签」 | 本项目输入框 44px（Filled 常规 56dp 的紧凑化），正属此档 |
| WCAG 3.3.2：「标签必须始终可见」 | 外部标签天然满足 |
| `design.md` §7.2：「标签置于输入框**上方**（左对齐，13px），不使用浮动标签 —— 后台数据密度高，浮动标签视觉噪声大」 | 沿用同一判断 |

> **结论：沿用「外部标签」方案，但补齐 Material 要求的 8 态状态机。**
> 这与 `design.md` §7.2 的后台约定一致，不引入第二套规范。

### 5.4 八态规格表

| 状态 | 底色 | 边框 | 文字 | 标签 | 附加 |
|---|---|---|---|---|---|
| 空值未聚焦 `idle` | `$color-surface-2` | `$color-border` 1px | `$color-text` | `$color-text-2` | — |
| 空值聚焦 `focused` | `$color-surface-2` | `$color-primary` **1.5px** | `$color-text` | `$color-primary` | 光标 `$color-primary` |
| 有值未聚焦 `filled` | `$color-surface-2` | `$color-border` 1px | `$color-text` | `$color-text-2` | — |
| 有值聚焦 `filled-focus` | `$color-surface-2` | `$color-primary` 1.5px | `$color-text` | `$color-primary` | — |
| 错误未聚焦 `error` | `$color-danger-tint` | `$color-danger` 1px | `$color-text` | `$color-danger` | 下方错误文字 + 错误图标 |
| 错误聚焦 `error-focus` | `$color-danger-tint` | `$color-danger` **1.5px** | `$color-text` | `$color-danger` | 同上 |
| 禁用 `disabled` | `$color-surface-3` | `$color-border` 1px | `$color-text-4` | `$color-text-3` | 不可聚焦 |
| 只读 `readonly` | `$color-surface-2` | `$color-border` 1px | `$color-text-2` | `$color-text-2` | 可聚焦不可改 |

### 5.5 聚焦边框加粗不抖动

Material 规范明确警告：描边式聚焦时边框 1px → 2px 会让内容位移 1px（「输入的时候字抖了一下」）。

**解法（小程序可行版）**：不真改 `border-width`，改用 `box-shadow` 模拟第二层边框（**不改变盒模型**）：

```scss
.field-input {
  background: $color-surface-2;
  border: 1px solid $color-border;          /* 恒定 1px，不抖 */
  border-radius: $radius-md;
  padding: 12px $space-3;                    /* 恒定，不随聚焦变 */
  min-height: 44px;
  font-size: $font-size-body;
  color: $color-text;
  box-sizing: border-box;
  transition: border-color $duration-fast $ease-standard,
              box-shadow   $duration-fast $ease-standard,
              background-color $duration-fast $ease-standard;
}
.field-input:focus {
  border-color: $color-primary;
  box-shadow: 0 0 0 3px $color-primary-tint;   /* 焦点环：白名单允许 */
}
```

> `box-shadow` 只用**一层**（`design.md` §5.3 同屏阴影层级 ≤ 1 种；焦点环属边框白名单）。
> 边框颜色过渡用 `$ease-standard`（属 Effects 类，不该过冲）。

### 5.6 错误态的三重信号

Material 规范：「**只靠红色传达『出错了』是常见误区**，色觉障碍用户分辨不出。规范的做法是颜色 + 图标 + 文案三重信号。」

```
┌────────────────────────────────────┐
│ ⚠ 学号                              │  ← 标签色转 danger
│ ┌────────────────────────────────┐ │
│ │ 8-12 位数字                   │ │  ← 边框 danger + 底色 danger-tint
│ └────────────────────────────────┘ │
│ ⓘ 学号为 8-12 位数字                │  ← 图标 + 文案（12px danger）
└────────────────────────────────────┘
```

### 5.7 字段错误定位顺序

WAI 多页表单：「出错时留在当前步、把焦点带到**错误摘要**或**第一个错误字段**」。

**本项目落地**：
1. 提交失败 → 保留所有已填内容（不清空）
2. 第一个错误字段加 `focus-ring` 样式（`box-shadow` 焦点环）
3. 页面自动滚动到该字段
4. 顶部轻提示（error）汇总：「有 2 项需要修改」
5. 不弹模态（除非是学号冲突这类阻断错误）

### 5.8 学号冲突（阻断 → 模态）

```
uni.showModal({
  title: '学号无法绑定',
  content: '该学号已绑定其他账号，请联系管理员处理。',
  confirmText: '知道了',
  showCancel: false,
});
```

> 依据微信设计指南三级报错：模态报错 = 「阻断并给出下一步操作指引」。
> 但**不得暴露「该学号存在」**（防学号枚举）→ 文案用「已绑定其他账号」而非「该学号不存在」。

## 第 6 章 动效系统重建（丝滑度）

### 6.1 核心认知：「丝滑」≠ 动画多

```
丝滑 =  节奏统一（同一类交互用同一时长与缓动）
      + 状态可预期（按下必有反馈、加载必有占位、错误必有定位）
      + 反馈有因果（动画方向 = 信息方向）
      + 无中断感（可被打断且能平滑接管）
```

### 6.2 M3 双体系 → 本项目双令牌

M3 官方定义（联网核验）：

| 类别 | 动画的属性 | 阻尼比 | 特性 |
|---|---|---|---|
| **Spatial**（空间动效） | 移动、缩放、旋转、圆角、morph | **< 1（欠阻尼）** | **会过冲**，有回弹 |
| **Effects**（效果动效） | 颜色、透明度 | **1.0（临界阻尼）** | **绝不回弹** |

> M3 原文警示：「An overshooting color looks broken, so **never use a spatial spec for it**.」

**本项目映射**（比 M3 更保守，因为 `design.md` 铁律⑤要求吸附类用过阻尼）：

| 交互类别 | 属性 | 令牌 | 阻尼 | 理由 |
|---|---|---|---|---|
| **结构位移**（弹窗进出、抽屉、卡片入场） | transform | `$ease-overdamped` | 过阻尼 | 位置确定，绝不晃（铁律⑤） |
| **效果变化**（颜色、透明度、阴影） | color / opacity / box-shadow | `$ease-standard` | 标准 | 不该过冲（M3 Effects ζ=1.0） |
| **积极反馈**（勾选、成功徽章） | scale | `$ease-underdamped` | 欠阻尼 | 回弹 ≤1.12 / ≤4px / 1 次（铁律⑤） |
| **按压** | scale(0.96) | `$ease-overdamped` | 过阻尼 | M3：按压用 effects 弹簧 ζ=1，「按压反馈不会回弹」 |

### 6.5 加载态（局部，不做全屏模态）

微信设计指南：
> 「**局部加载反馈**即只在触发加载的页面局部进行反馈，有针对性，页面跳动小，是**微信推荐的反馈方式**。」
> 「**模态加载**……由于无法明确告知具体加载的位置或内容，可能引起用户的焦虑感，因此应谨慎使用。」

**本项目落地**：
- 主按钮内联 loading（按钮变 spinner + 文案变「登录中…」），**不遮罩全屏**
- 按钮 `disabled` + `opacity: 0.6`（防连点）
- 学校列表加载：字段区显示 skeleton（3 行 `surface-2` 块，`opacity` 脉动）
- 组织级联切换：picker 内显示「加载中…」

### 6.7 减少动效（prefers-reduced-motion）


```python
def resolve_phone(self, phone_code: str | None, phone: str | None) -> str:
    """解析手机号：生产只接受微信 phone_code；直传 phone 仅 Mock 联调态放行。"""
    if phone_code and phone_code.strip():
        if self.is_mock:
            raise ExternalServiceError(
                "Mock 模式无法通过 code 解析手机号，请在开发联调开关内直传 phone"
            )
        return self._phone_by_code(phone_code.strip(), self._openid_hint())
    if phone and phone.strip():
        if not self.is_mock:
            raise PermissionDeniedError("生产环境不接受直传手机号，请使用微信手机号授权")
        return phone.strip()
    raise ExternalServiceError("缺少手机号凭证")
```

**决策：保留，但收进「其他方式」折叠项，且默认折叠。**
